# مدیریت گالری نگار الماسی — نسخه Pages CMS

این نسخه **در کنار همان GitHub Pages موجود** کار می‌کند؛ آدرس سایت و QR رزومه عوض نمی‌شود.

- سایت عمومی: https://negar-almasi-gallery.github.io/Portfolio/
- ورودی ساده مدیر: https://negar-almasi-gallery.github.io/Portfolio/admin/
- پنل واقعی: https://app.pagescms.org/
- مخزن آثار: https://github.com/negar-almasi-gallery/Portfolio

## یک بار برای فعال‌سازی پنل

1. با حساب **negar-almasi-gallery** وارد https://app.pagescms.org/ شوید.
2. گزینه **Sign in with GitHub** را انتخاب کنید.
3. در نصب GitHub App حتماً **Only select repositories** و مخزن **Portfolio** را انتخاب کنید. رمز و کد ورود را با کسی به اشتراک نگذارید.
4. از فهرست CMS مخزن `negar-almasi-gallery/Portfolio` و شاخه `main` را انتخاب کنید.
5. مجموعه **آثار هنری** را باز کنید. دو اثر موجود باید از قبل نمایش داده شوند.

**نکته:** اتصال Pages CMS از اتصال GitHub به ChatGPT جداست و آن را تغییر نمی‌دهد.

## افزودن اثر (بدون ویرایش کد)

1. در **آثار هنری** روی افزودن اثر جدید بزنید.
2. عنوان، توضیح، تکنیک و دسته‌بندی را پر کنید.
3. ویدیو MP4 را انتخاب یا بارگذاری کنید. عکس جلد اختیاری است؛ در نبود آن، سایت زمینه زرد نشان می‌دهد.
4. **منتشر شود؟** در ابتدا خاموش است. ابتدا ذخیره کنید و اطلاعات را بازبینی کنید.
5. وقتی مطمئن شدید، وارد همان اثر شوید، **منتشر شود؟** را روشن کنید و ذخیره کنید.
6. پس از موفقیت انتشار GitHub Pages، کارت اثر در سایت عمومی اضافه می‌شود. QR قبلی ثابت است.

### ویدیوهای بزرگ‌تر از حدود ۴ مگابایت

نسخه میزبانی‌شده Pages CMS در گذشته برای بارگذاری فایل‌های بزرگ با محدودیت سمت سرور (HTTP 413) مواجه بوده است. این موضوع **با محدودیت آپلود GitHub فرق دارد** و به همین دلیل قول نمی‌دهیم فایل‌های ۷ تا ۲۳ مگابایتی در CMS بارگذاری شوند.

راه مطمئن‌تر برای چنین ویدیوهایی:

1. با حساب نگار وارد پوشه https://github.com/negar-almasi-gallery/Portfolio/tree/main/videos شوید.
2. **Add file → Upload files** را بزنید و فایل MP4 جدید را بارگذاری کنید (از مرورگر GitHub هر فایل حداکثر ۲۵ MiB).
3. Commit کنید. چون سایت جدید فقط اطلاعات آثارِ دارای وضعیت «منتشرشده» را نشان می‌دهد، بارگذاری ویدیو **به تنهایی کارت عمومی ایجاد نمی‌کند**.
4. به Pages CMS برگردید و در فرم اثر، ویدیوی آپلودشده را از **رسانه‌های موجود** انتخاب کنید.
5. اگر انتخاب فایل موجود در CMS کار نکرد، مسیر کامل `/Portfolio/videos/NAME.mp4` را از ما بخواهید تا برای همان اثر وارد کنیم؛ توکن شخصی یا دسترسی محرمانه لازم نیست.

### عکس جلد

عکس‌های JPG/PNG/WebP را می‌توان از داخل فیلد «تصویر جلد» آپلود یا انتخاب کرد. در صورت محدودیت، عکس را جداگانه در پوشه https://github.com/negar-almasi-gallery/Portfolio/tree/main/posters بگذارید و در CMS انتخاب کنید. بهتر است پیش از آپلود حجم عکس زیر ۱ مگابایت باشد.

## ویرایش، پیش‌نویس، حذف

- **ویرایش:** روی اثر در فهرست کلیک کنید، فیلدهای موردنظر را تغییر دهید و ذخیره کنید.
- **پنهان‌کردن:** وضعیت «منتشر شود؟» را خاموش و ذخیره کنید. داده‌ها و رسانه‌ها باقی می‌مانند ولی کارت از سایت حذف می‌شود.
- **حذف اثر:** از دستور حذف در لیست CMS استفاده کنید. این دستور فایل مشخصات همان اثر را حذف می‌کند و پس از انتشار، کارت از سایت ناپدید می‌شود.
- **پاک‌سازی رسانه:** حذف رکورد لزوماً فایل ویدیو یا عکس را از مخزن حذف نمی‌کند. برای آزادکردن فضا، فایل‌های دیگر مورد استفاده نبودۀ آن را جداگانه از پوشه‌های videos و posters پاک کنید؛ پیش از حذف مطمئن شوید در اثر دیگری استفاده نشده باشند.
- **جایگزینی ویدیو/عکس:** فایل جدید را بارگذاری کرده، فیلد مربوطه را در اثر تغییر دهید و ذخیره کنید. پس از بررسی، فایل رسانه قدیمی و بلااستفاده را می‌توان جداگانه حذف کرد.

## نکات فنی برای توسعه‌دهنده

- `.pages.yml` پیکربندی پنل است؛ تغییرات محتوا از طریق Pages CMS به GitHub commit می‌شود.
- اطلاعات هر اثر به صورت YAML مستقل در `_data/portfolio/*.yml` ذخیره می‌شود.
- سایت Jekyll فقط آثاری را نشان می‌دهد که `published: true` و `video` معتبر داشته باشند.
- مسیر رسانه‌ها از پیش با `/Portfolio/videos/` و `/Portfolio/posters/` تنظیم شده است.
- ساختار قدیمی `_data/artworks.yml` برای بازگشت به نسخه قبل نگه داشته شده و دیگر در گالری خوانده نمی‌شود؛ بعد از تأیید کامل می‌توان آن را حذف کرد.
- در صورت نیاز برای تصویرسازی خودکار از فریم ویدیو باید یک پردازش مستقل (GitHub Actions / FFmpeg) اضافه کنیم؛ این نسخه چنین چیزی را ادعا نمی‌کند.
- مخزن عمومی است. حتی آثار «پیش‌نویس»، اگر فایل رسانه آن‌ها در مخزن Public آپلود شده باشد، از طریق خود GitHub قابل مشاهده‌اند؛ فقط در سایت عمومی نمایش داده نمی‌شوند.
- نام فایل جدید توسط CMS زمان‌محور ساخته می‌شود تا کاربر لازم نباشد slug یا YAML بنویسد.

## محدودیت‌ها و بررسی بعد از انتشار

بعد از بارگذاری فایل‌های این بسته باید در حساب نگار Pages CMS را با GitHub نصب و متصل کنید؛ بدون احراز هویت صاحب حساب، پنل قابل راه‌اندازی نهایی نیست. بهتر است یک «اثر آزمایشی پیش‌نویس» بسازید، ویرایش کنید، منتشر کنید و سپس حذف کنید تا رفتار واقعی نسخه میزبانی‌شده آزمایش شود. اگر CMS خطای بارگذاری، ذخیره یا انتخاب رسانه نشان داد، متن خطا را برای بررسی بفرستید.
